### 3. Flutter は 3 つの層 `/r-architecture` — 3ステップ

**JP**
> ⏎ 一番上が Framework。Dart で書かれていて、私たちが書くのはここ。Widget も RenderObject もここにいます。
> ⏎ その下が Engine。C++ で書かれていて、Impeller がピクセルを描き、Dart のランタイムも動いています。
> ⏎ 一番下が Embedder。iOS、Android、Web、デスクトップ……OS とつなぐ部分です。
> プラットフォームごとに違うのはこの一番下だけ。上の 2 層は全部共通です。

### 4. Impeller `/r-impeller` — 1ステップ 🖱

**JP**
> 描画エンジンの名前は Impeller です。昔は Skia を使っていました。
> *🖱 Skia のまま「新しいアニメーションを初表示」を押す* ── 赤い棒が飛び出ましたね。

### 23. メッセージがチャンネルを通る旅 `/n-channel-sim` — 1ステップ 🖱

**JP**
> 中で何が起きているか見てみましょう。
> *🖱 「getBatteryLevel() を呼ぶ」* ── メッセージが Dart を出発して、
> Codec でバイト列になります。07 は「文字列」、0F は 15 文字、続く数字が getBatteryLevel の文字コードです。
> プラットフォームスレッドに届いて、Swift のハンドラーがバッテリー残量を取ってきて……返事もバイト列で戻ってきます。00 が成功、03 が整数。
> その間、左上のアイコンはずっと回っています。待っている間も UI は止まりません。

### 24. Pigeon `/n-pigeon` — 4ステップ

**JP**
> ただ、MethodChannel は文字列で名前を合わせるので、タイプミスすると実行時までわかりません。
> ⏎ そこで Pigeon。インターフェースの定義を 1 回書くだけ。
> ⏎ そこから Dart、Swift、Kotlin のコードを生成してくれます。
> ⏎ 名前や型のミスはコンパイル時にわかります。
> ⏎ 今はプラグインを作るときの推奨デフォルトです。

---

### 25. FFIgen：Dart から OS の API を直接呼ぶ `/n-ffigen` — 1ステップ

**JP**
> そして最近の大きな変化がこれ。FFIgen です。
> 設定ファイルに「UIDevice を使いたい」と書くと、Objective-C のヘッダーから Dart のコードを生成してくれます。
> すると Dart から UIDevice を直接、しかも同期的に呼べる。await もチャンネルもいりません。
> Android には同じ発想の jnigen があって、Java や Kotlin の API を直接呼べます。C や C++ のコードも、build hooks でパッケージに同梱できるようになりました。
> Swift は今のところ @objc 経由で、純粋な Swift 向けの swiftgen はまだ実験的です。
