### 10. ツリーは3本ある `/t-three` — 3ステップ

**JP**
> ⏎ 1本目は Widget。設計図です。不変で軽い。毎フレーム作り直しても平気です。

### 12. なぜ3本に分けるのか `/t-why` — 3ステップ

**JP**
> ⏎ build は何度でも呼ばれます。Widget は毎回捨てて作り直す。
> ⏎ でも Element は、新しい Widget の「型」と「key」が前と同じなら、使い回します。これが `canUpdate`。
> ⏎ だから重い RenderObject も、State も生き残る。作り直しているのは設計図だけで、実体は差分だけ更新される。だから Flutter は速いんです。

### 15. 信号のチューブ `/j-tube` — 10ステップ

**JP**
> 左から Widget、Element、RenderObject、そして右がスマホです。このチューブを、タップの信号が旅していきます。
> ⏎ ① 指が触れる。OS からエンジンにタッチが届き、Dart 側の GestureBinding に PointerDownEvent が来ます。
> ⏎ ② ヒットテスト。「どこを触った？」を、一番上の RenderView から順に問い合わせていきます。答えは FAB の中の RenderPointerListener。触られた RenderObject のリスト、HitTestResult ができます。
> ⏎ ③ ジェスチャーアリーナ。イベントが届いて、TapGestureRecognizer が「これはタップです」と勝ち名乗りを上げます。実際に確定するのは指を離したときです。
> ⏎ ④ ここでやっと私たちのコード。onPressed → `_incrementCounter()` → setState。チューブは Element に入ります。
> ⏎ ⑤ setState は、Element に「dirty」の印をつけるだけ。BuildOwner が覚えておいて、次のフレームを予約します。この時点では、まだ何も描き直していません。
> ⏎ ⑥ 次の vsync。drawFrame → buildScope で、印のついた Element の build() が呼ばれ、新しい Widget が生まれます。
> ⏎ ⑦ Element が新旧を比べます。型が同じなので使い回し。RenderParagraph の文字だけを「1」に書き換えて、markNeedsLayout。
> ⏎ ⑧ レイアウト、ペイント、合成。PipelineOwner が汚れた RenderObject だけを計算し直して、レイヤーツリーをエンジンに渡します。
> ⏎ ⑨ エンジン（Impeller）が GPU でラスタライズ。画面に「1」。
> ここまでで、ほぼ1フレーム。60fps なら 16ミリ秒の旅です。

*🖱 最後にスマホの ＋ をタップすると、①〜⑨が自動再生される。ゆっくりもう一度見せたい時に。*

### 17. setState の中身 `/j-setstate` — 3ステップ

**JP**

### 18. 1フレームのパイプライン `/j-frame` — 1ステップ

**JP**
> ⑥〜⑨ をまとめると、これが1フレームの流れです。vsync、アニメーション、ビルド、レイアウト、ペイント、合成、ラスタライズ。
> 60fps なら 16.7ミリ秒、120fps なら 8.3ミリ秒に全部を収めないといけません。
> スライダーで、毎フレーム重い処理を入れてみます。…16ミリ秒を超えた瞬間、ボールがカクカクに。これが「ジャンク」です。
> build や重い計算を UI スレッドでやりすぎない。これがパフォーマンスの基本です。

*🖱 スライダーを 0 → 10ms（まだ大丈夫）→ 25ms（カクつく）→ 0 に戻す。*

### 22. State の一生 `/w-lifecycle` — 1ステップ

**JP**
> State には一生があります。右のログに、呼ばれたメソッドがリアルタイムで出ます。
> 最初に createState、initState、didChangeDependencies、build。
> setState を押すと、build だけ。props、つまり親から渡す値を変えると didUpdateWidget → build。
> 上の InheritedWidget を変えると didChangeDependencies。
> アンマウントすると deactivate → dispose。後片付けは dispose で。

*🖱 setState → props を変える → InheritedWidget を変える → アンマウント → マウント の順に押す。*

### 23. InheritedWidget `/w-inherited` — 3ステップ

**JP**
> ⏎ InheritedWidget は、ツリーの上に置いておくと、下のどこからでも値を取れる仕組み。
> ⏎ `dependOnInheritedWidgetOfExactType` で依存すると、値が変わったときにその Widget だけが再ビルドされます。
> ⏎ 毎日使っている `Theme.of(context)` や `MediaQuery.of(context)` も、この仕組みです。後半の状態管理の話の土台になります。

---

### 24. Widget の家系図 `/w-family` — 4ステップ

**JP**
> ⏎ StatelessWidget：組み立てるだけ。
> ⏎ StatefulWidget：状態を持つ。
> ⏎ RenderObjectWidget：実際に描いたり並べたりする。子が0個・1個・複数で3種類。Padding も Row も、ここです。
> ⏎ ProxyWidget：情報を渡す。InheritedWidget や、Expanded・Positioned のような親にレイアウト情報を伝える ParentDataWidget。
> 画面に何かを描くのは RenderObjectWidget だけ。ほかは組み立て役と橋渡し役です。
